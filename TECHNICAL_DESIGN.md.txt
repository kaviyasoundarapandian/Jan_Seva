# Jan Seva — Technical Design

## 1. Goals

- One app for everyday citizen services in India, usable by anyone, in their own language.
- Works with no sign-up and with weak connectivity; sensitive data never leaves the device.
- Single deployable artifact (`index.html`) that runs in a browser and inside an Android WebView.

## 2. Architecture

```
┌────────────────────────── Android app (WebView shell) ──────────────────────────┐
│  assets/index.html  ·  assets/model.json  ·  assets/metadata.json               │
│  Served through WebViewAssetLoader → https://appassets.androidplatform.net/...  │
└──────────────────────────────────────────────────────────────────────────────────┘
                                   │ same file also runs in any browser
                                   ▼
┌────────────────────────────── index.html (SPA) ──────────────────────────────────┐
│  UI layer     : header (language, profile) · search · tile grid · bottom nav     │
│  View layer   : V.<name>() functions return HTML strings, render() swaps them    │
│  Router       : go(name) + data-go attributes + delegated click handler          │
│  i18n         : t(key) dictionaries, 22 languages, bilingual labels (EN/HI)      │
│  State        : in-memory vars (prof, reports, contacts, places, rem, S, PN …)   │
│  Storage      : ld(k,default)/sv(k,value) → localStorage "ns_<k>" (JSON)         │
│  Add-ons      : IIFE modules that wrap/extend V.* (health, pay, radio, security) │
│  Device APIs  : geolocation, camera, mic, speech, vibration, notifications,      │
│                 DeviceMotion, Web Bluetooth, clipboard, share, service worker    │
│  ML           : TensorFlow.js + Teachable Machine image model (sign language)    │
└──────────────────────────────────────────────────────────────────────────────────┘
                                   │ outbound only, user-initiated
                                   ▼
  Open-Meteo (forecast) · Google Maps / OSM links · Bhashini · official .gov.in portals
```

### Key design decisions

| Decision | Reason |
|---|---|
| Single HTML file | Easy to host, audit, cache and bundle into the APK |
| No backend | Zero hosting cost, no personal data collection, works offline after first load |
| Views as HTML-string functions | No framework needed; tiny runtime; easy to wrap with add-ons (`var o=V.home; V.home=function(){…o()…}`) |
| Event delegation with `data-*` | One click listener handles all actions (`data-go`, `data-sv`, `data-hx`, `data-del` …) |
| Links to official portals | Jan Seva guides users, it never handles OTPs, Aadhaar numbers or payments |
| Local-only profile | Privacy; guest mode is the default |

## 4. Data model (localStorage, prefix `ns_`)

All values are JSON. `ld(key, default)` reads, `sv(key, value)` writes.

| Key | Shape | Purpose |
|---|---|---|
| `lang` | `"en"` | UI language code |
| `guest` | `true/false` | Guest mode chosen |
| `prof` | `{n, a, s, q, bg, dt, h, sl}` | Profile: name, age, state, qualification code, blood group, date, PIN hash `h`, salt `sl` |
| `sec` | object | Password / second-factor settings (PBKDF2) |
| `contacts` | `[{n, p}]` | SOS contacts (name, phone) |
| `reports` | `[{id, cat, desc, photo, loc, anon, at, done, rating}]` | Civic reports; `cat` is 1–14, `loc` = `{lat,lng}`, `photo` = data URL |
| `nsRem` | `{reportId: timestamp}` | Last "no reply" reminder per report |
| `places` | `[{c, n, tm, lat, lng}]` | Saved places (category index, name, time) |
| `rem` | `[{n, d}]` | Exam / medicine reminders (name, `YYYY-MM-DD`) |
| `qual` | `"grad"` | Qualification for guests |
| `hx` | `{d, steps, glass, meals[3], hr, goal, wmin, food, auto, lw, lm}` | Daily health state, reset each day |
| `pen` | `{type, amt, day, rec:[{m, a}]}` | Pension tracker |
| `sav_g` | `[{n, t, s, m}]` | Savings goals (name, target, saved, monthly) |
| `sav_b` | `{inc, need, want}` | Income split |
| `x16my`, `x16st`, `x16loc`, `x16ph`, `x16gl` | various | Officials directory (saved entries and filters) |
| `nanba`, `nb_api` | array / string | Nanba chat history and optional API setting |
| `wxLoc`, `dsLoc`, `dsAuto`, `dsSeen`, `gps` | various | Weather / disaster location and alert state |
| `donor`, `bdtap`, `bvl`, `bwake` | various | Blood donation, tap/wake helpers |
| `notes`, `sleep`, `wt`, `cal_*`, `rad`, `acc`, `sgn`, `ul` | various | Notes, sleep, weight, calendar, radio, accessibility, sign-language and UI flags |

Photos are stored as data URLs; if `localStorage` is full the app shows a "storage full" toast.

## 5. Feature design notes

**Emergency / SOS.** `tel:` links for 112/108/100/101. SOS gets the GPS fix, builds an SMS containing a Google Maps link and opens the SMS composer for every saved contact. Nothing is sent to a server.

**Reports.** A report needs a description or a photo. It gets a short code (`id`) the user can quote. Statuses: open → resolved (`done`), plus a 1–5 `rating`. A timer flags reports with no reply for 7+ days (stored in `nsRem`).

**Disaster alerts.** Uses the Open-Meteo forecast API for the user's coordinates (next 3 days), flags heavy rain, wind, thunderstorm, extreme heat. Optional auto-check every ~30 minutes and a local notification. Always labelled "indicative, not official — follow IMD / local authority".

**Health.** Step counter via `DeviceMotion`; heart rate by manual entry or Web Bluetooth; water and meals; reminders via the Notifications API; optional fall/impact detection with a 15-second countdown before it calls 108/112.

**Translator & voice.** Browser SpeechRecognition for input, SpeechSynthesis for output, translation through a Google Translate / Bhashini hand-off (needs internet).

**Sign language.** `model.json` + `metadata.json` (TF.js 3.18 Teachable Machine) with labels: உதவி (help), डॉक्टर (doctor), மருத்துவமனை (hospital), போலீஸ் (police), தண்ணீர் (water), மருத்துவம் (medicine), வலி (pain), ஆம் (yes), No, நன்றி (thanks). Runs on-device via the camera.

**Security.** If the user sets a PIN/password, a random salt is generated with `crypto.getRandomValues` and the secret is hashed with PBKDF2 (`crypto.subtle`); only the hash and salt are stored. Wrong PIN shows a toast; "Not you?" deletes the local profile after confirmation.

**i18n.** `t(key)` looks up the active language; missing keys fall back to English. Labels that are bilingual (`"English / हिन्दी"`) show both parts for English and Hindi and only the English part for other languages.

## 7. Android packaging

Permissions: `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, `CAMERA`, `RECORD_AUDIO`, `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE`, `RECEIVE_BOOT_COMPLETED`, `WAKE_LOCK`. The WebView must enable JavaScript, DOM storage and a geolocation/permission-request handler, and load the page via `WebViewAssetLoader`.

## 8. Performance and accessibility

- ~600 KB single file; views render on demand (no framework, no build step).
- Large touch targets, high-contrast palette (navy / saffron / green), `aria-label`s on icon buttons, semantic headings, voice input and text-to-speech, sign-language tool.
- Right-to-left layout handling for RTL scripts (Urdu, Sindhi, Kashmiri).

## 9. Known limitations / roadmap

- The page registers `sw.js` for offline caching; add a `sw.js` next to `index.html` when hosting on the web (it is not part of the APK assets). Weather, maps, translation and news need internet.
- `localStorage` is device-specific: no cross-device sync or cloud backup yet (export/import is a planned feature).
- Photo size is limited by `localStorage` quota; compress images before saving (planned).
- Translations for some of the 22 languages fall back to English for rarely used strings.
- Planned: Play Store release, scheme eligibility checker with offline data, report hand-off to municipal portals, backup to file.
